**MQTT 是什么（面试就这么答）**

MQTT 是物联网最常用的轻量级消息协议，基于**发布/订阅**模式，跑在 TCP 上。三个角色：设备是**发布者**，把数据发到某个**主题（Topic）**上；中间有个**Broker**（消息代理服务器，常见的有 EMQX、Mosquitto）负责中转；平台是**订阅者**，订阅了主题就能实时收到数据。

30 秒话术，背下来直接说：

> "MQTT 报文特别小、省电省流量，专为弱网和大量设备设计的。设备连上 Broker 后，把温湿度、电量这些数据发布到指定 Topic，平台订阅就能实时收到；平台下发控制指令也是往设备的 Topic 发。它还有 QoS 质量等级和遗嘱消息机制，设备掉线能自动发通知，所以特别适合楼宇里成百上千个传感器的上报和在线状态监测。"

大概率追问，提前备好：
- **QoS 三个等级**：0 最多发一次，可能丢；1 至少一次，可能重复；2 恰好一次，最可靠也最耗资源。控制指令一般用 1，普通状态上报 0 或 1 就够
- **和 HTTP 比**：HTTP 是一问一答的请求模式、开销大；MQTT 是长连接、能双向推送、报文最小才 2 字节
- **Topic 通配符**：`+` 匹配一层，`#` 匹配多层，比如订阅 `楼宇/#` 能收整栋楼的数据
- **遗嘱消息**：设备连接时预设一条"遗嘱"，异常掉线时 Broker 自动帮它发出去，平台立刻知道它下线了

**三大协议分工**（必考，原样背）：
**Modbus 管设备**——电表、水表、PLC 的数据采集；**BACnet 管楼控**——暖通、照明、电梯这些系统之间互通；**MQTT 管上云**——把数据传到平台。

**快速模拟题（问题+答法框架，过一遍）**

1. **某个传感器数据突然不上报了，怎么排查？** 按链走：设备供电 → 采集网关 → 网络通不通（ping、交换机端口、VLAN）→ 协议配置（地址、Topic 对不对）→ 平台服务（Broker 连没连上、数据库有没有落库）→ 看日志定位在哪一环断的
2. **Nginx 报 502？** 先看后端服务活没活、端口对不对，再看 Nginx 错误日志，顺带查防火墙和后端进程
3. **MySQL 慢查询？** 开慢查询日志定位 SQL，explain 看有没有走索引，再加索引或改 SQL
4. **Redis 在平台里干嘛？** 缓存设备最新状态和热点数据、存会话，减轻数据库压力；持久化是 RDB 加 AOF
5. **VLAN 是什么？** 在交换机上逻辑划分网段、隔离广播域。楼宇里常把安防、办公、设备网分开，互不干扰也更安全
6. **客户反复催一个没修好的问题，怎么办？** 先响应、先给明确时间点，修的过程中主动同步进展，修好后做记录闭环——这岗位一半是服务，别等客户追着问
7. **你没做过智慧楼宇，凭什么能干？** 诚实桥接：楼宇业务我确实在补，但平台底下就是 Linux 服务器加数据库加网络，这套是我干了几年的老本行；BA、安防、能耗这些系统的运维逻辑是通的，上手不会慢。**千万别编楼宇项目经历**，驻场的人一追问细节就穿
8. **最后你反问他**（显得你认真）：日常工作里运维、对接客户、做报表大概各占多少？驻场是几个人？值班怎么安排？

证书那些加分项没有就大方说没有，别硬编。中电信数智是电信旗下的政企口，稳定性、服务意识、响应速度看得比技术深度还重，答运营类问题时往"响应快、闭环好"上靠就对了。
